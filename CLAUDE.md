# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A **monorepo web application** (Next.js + FastAPI) — an interactive teaching tool for visualizing how LLMs work (Chinese-language UI). See `README.md` for the full feature/design spec and `AGENTS.md` for contributor conventions.

**Status**: Migrated to a monorepo (Next.js + FastAPI). Specs 001–008 (scaffold → deploy) and **009–013 (teaching content → SQLite)** are merged on `junxiang`. The old root `*.dc.html` / `support.js` / `Job.data.js` files are kept as historical reference only — **do not edit them**; all work happens under `apps/` and `packages/`.

## Commands

```sh
# Backend (FastAPI)
cd apps/api
python -m app.db.seed_content              # import teaching content (idempotent)
uvicorn app.main:app --reload --port 8000
python -m pytest tests/ -q                 # backend tests

# Frontend (Next.js)
cd apps/web
npm install
npm run dev                                # http://localhost:3000
npm run typecheck                          # tsc --noEmit
```

The frontend proxies `/api/*` to the backend (`next.config.ts` rewrites). Dev startup auto-seeds content unless `SEED_CONTENT_ON_STARTUP=0`.

## Architecture — monorepo

- `apps/web` — Next.js + React + TypeScript. App Router pages under `src/app/{,/lab,/code,/jargon,/job}/page.tsx`; shared components in `src/components`; API/SSE clients in `src/lib`. Pages are client components that `fetch` from `/api/*`.
- `apps/api` — FastAPI. Layered: `routers/` (health, chat, conversations, **content**) → `services/` → `db/` (aiosqlite). Provider adapters in `adapters/` (OpenRouter / AIHubMix / Packy / Custom).
- `packages/shared` — cross-layer TypeScript types (`@teaching-tool/shared`), transpiled into the web app. Backend Pydantic models in `apps/api/app/models/` mirror these.

### Teaching content lives in SQLite (Spec 009, reused by 010–013)
- Three module-agnostic tables in `apps/api/app/db/schema.py`: `content_categories`, `content_items` (filter/sort columns promoted; full doc in a JSON `payload`), `content_meta` (page-shape data). Keyed by `(module, item_type, slug)`.
- **JSON fixtures are the single source of truth**: `apps/api/app/db/seeds/content/<module>/*.json`. The runtime `.db` is gitignored and generated by the seeder.
- `apps/api/app/db/seed_content.py` holds a `MODULE_REGISTRY`: each module has a `loader()` returning `(categories, items, meta)`; the seeder upserts idempotently via `content_hash` and asserts expected counts (fails loudly on mismatch).
- Read API: `GET /api/content/{jargon,jobs,code,lab,chat/pipeline}` (+ `/jobs/{id}`), read-only/public, `Cache-Control: public, max-age=300`.

### Chat (the only page that calls a real LLM)
- `apps/web/src/app/page.tsx` + `lib/{api,sse-client}.ts`: builds a request, streams SSE from `POST /api/chat/stream`. API keys live **only** in browser `localStorage['llm_viz_settings']` and are forwarded transiently by the backend — never persisted/logged.
- Anonymous sessions + conversations persist in SQLite (Spec 003); 30-day expiry; hashed IP/UA only.

## Conventions

- **Design system is fixed** (dark terminal aesthetic). Do not introduce new colors or fonts. Only main accent is brand green `#00ffa0`; secondary accents from existing blue/purple/orange. Fonts: JetBrains Mono (code/data/labels) and Inter (prose) only.
- Styling is inline `style={}` in components (no CSS modules/Tailwind); shared resets in `apps/web/src/app/globals.css`.
- Handler/state names are descriptive verbs (`toggleSettings`, `setModel`).
- Spec Kit workflow: each feature is a numbered Spec under `specs/NNN-*` (`spec → plan → tasks → analyze → implement → merge`), 5 commits + a merge into `junxiang`. Commit messages mostly Chinese; `.db` and API keys never committed.

## Adding a teaching-content module (the 009 pattern, reused by 010–013)
1. Add fixtures `apps/api/app/db/seeds/content/<module>/*.json`.
2. Write `_load_<module>()` in `seed_content.py` returning `(categories, items, meta)`; register it in `MODULE_REGISTRY` with `expected_categories/expected_items`.
3. Add a `content_service.py` read function + a `routers/content.py` endpoint + Pydantic models in `models/content.py`.
4. Add the TS types in `packages/shared/src/content.ts` (re-export from `index.ts`); build/refactor the page in `apps/web/src/app/<module>/page.tsx` to fetch from the endpoint.
5. Add a contract test + seeder count assertion in `apps/api/tests/`.
